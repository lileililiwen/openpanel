# Add Preview deployments — Design

## Explore & Reuse

- `crates/openpanel-domain/src/git_deployment/` — `webhook_secret`
  (:103) and `DeployRepository` trait (:163): the signed-webhook
  requirement (`openspec/specs/git-deployment/spec.md`) is reused
  verbatim; PR events are a new arm of the same dispatcher.
- `crates/openpanel-domain/src/site_staging/slot.rs:101` —
  `StagingSlot` + Atomic Promote (`openspec/specs/site-staging/spec.md`):
  previews ARE slots with `purpose = Preview`; promote stays
  impossible from preview → production (only staging promotes).
- `openspec/specs/dns/spec.md` zone-template records: preview wildcard
  `*.pr.<site>` A record created through the dns module port.
- `openspec/specs/ssl/spec.md` + archived wildcard DNS-01 change:
  one wildcard cert for `*.pr.<preview-base>` covers all previews.
- `openspec/specs/app-runtimes/spec.md` Runtime Lifecycle Control:
  preview slot runs the same supervisor unit shape as runtime apps.
- Reaper precedent: monitoring/cron background tasks via
  `Module::background_tasks`.
- Audit: `PreviewCreated`, `PreviewReady`, `PreviewDestroyed{reason}`.

## State machine

```
             webhook(opened/synchronize)
Creating ───────────────► Building ──► Ready
   │                          │          │ ttl expiry / pr closed / cap evict
   └── error ──► Failed       └──► Failed      ▼
                                            Destroyed
```

Transitions are pure functions on `PreviewEnvironment` (unit-tested);
side effects live in the app service.

## URL & TLS

- Config: `[git_deployment.previews] base_domain = "pr.example.com",
  ttl_hours = 72, max_per_repo = 3, enabled = false`.
- Routing: one nginx server block per preview slot generated by the
  sites renderer (same pipeline as site-http-controls splice point),
  proxying to the slot's runtime port.
- TLS: single wildcard cert `*.pr.example.com` issued once via DNS-01;
  HTTP-01 fallback rejected for previews (per-PR hosts would each need
  challenges).

## Isolation

- Slot docroot/db placeholder namespaced `<site>-pr<pr>`; env vars
  injected into the runtime unit mark `PREVIEW=1`; WAF and
  bandwidth accounting treat previews as their own resource so quota
  counters stay separate.

## Webhook dispatch

```
handle_webhook(payload):
    verify signature (existing)
    match event:
      pull_request opened|synchronize -> upsert_preview(repo, branch, pr)
      pull_request closed             -> destroy_preview(reason = "pr_closed")
      push                            -> existing branch deploy path
```

## Endpoints / CLI / Web

```
GET    /api/v1/sites/{id}/previews
POST   /api/v1/sites/{id}/previews/{pr}/redeploy
DELETE /api/v1/sites/{id}/previews/{pr}
CLI: openpanel site preview {list,redeploy,destroy}
Web: Sites → Previews tab (state badges, TTL countdown, logs link)
```
