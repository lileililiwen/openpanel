## ADDED Requirements

### Requirement: Strict Spec-Test Drift Ratchet

The spec-test drift gate (`scripts/check-spec-test-drift.sh`) MUST
distinguish capabilities that were already uncovered when this
change shipped from capabilities that are uncovered because a
reviewer just added or modified them. In `--strict` mode, only the
latter MUST fail the build; the former are recorded in a reviewed
baseline file (`openspec/specs/.spec-test-drift-baseline`) and
treated as tracked debt. The baseline only shrinks.

#### Scenario: New uncovered capability fails

- **WHEN** a capability is added to `openspec/specs/` (or an
  existing capability's scenarios are modified) and no test
  references its name
- **THEN** `make spec-test-drift-strict` fails the build and names
  the capability.

#### Scenario: Pre-existing gap in baseline passes

- **WHEN** a capability is listed in
  `openspec/specs/.spec-test-drift-baseline` and has no covering
  test
- **THEN** `make spec-test-drift-strict` reports the gap as tracked
  debt and exits zero.

#### Scenario: Baseline is regenerated by a reviewed change

- **WHEN** a reviewer runs
  `scripts/check-spec-test-drift.sh --write-baseline`
- **THEN** every currently-uncovered capability is written to the
  baseline; the script never shrinks the baseline itself (entries
  must be removed by a reviewed edit to the file).

### Requirement: Strict Reuse Classification

The reuse gate (`scripts/check-reuse.sh`) MUST support a
classified-duplicates baseline (`openspec/governance/.reuse-classified-baseline`).
In `--strict` mode, only unclassified cross-crate public duplicates
MUST fail the build. The mandatory `make check` chain runs
`reuse-strict`, so a new unclassified duplicate fails CI by
default. The baseline only shrinks: removing entries is permitted
(after the duplicate is fixed), adding entries requires a reviewed
change.

#### Scenario: New unclassified duplicate fails

- **WHEN** a new public item is added that duplicates an existing
  one across crates and the duplicate name is not in the classified
  baseline
- **THEN** `make reuse-strict` fails the build and names both
  owners.

#### Scenario: Classified duplicate passes strict mode

- **WHEN** a duplicate public item is listed in
  `openspec/governance/.reuse-classified-baseline` with a reason
- **THEN** `make reuse-strict` reports it as classified debt and
  exits zero.

### Requirement: Coverage Floor and Tool Availability

Required CI coverage MUST be enforced by a dedicated job
(`make coverage-floor`) and MUST use a configured, supported tool
(`cargo-llvm-cov` is the canonical choice). The gate MUST fail when:

- the measured line coverage drops below the configured floor
  (`OPENPANEL_COVERAGE_FLOOR`, default 60), OR
- the tool is unavailable in a required CI job
  (`OPENPANEL_COVERAGE_REQUIRED=1`).

The informational `make coverage` target stays non-blocking for
local development.

#### Scenario: Coverage above floor passes

- **WHEN** the measured line coverage is at or above the configured
  floor
- **THEN** `make coverage-floor` exits zero.

#### Scenario: Coverage below floor fails

- **WHEN** the measured line coverage is below the configured floor
- **THEN** `make coverage-floor` exits non-zero and reports the
  measured percentage and floor.

#### Scenario: Tool missing in required job fails

- **WHEN** the required CI job cannot find `cargo-llvm-cov` (or its
  configured alternative) AND `OPENPANEL_COVERAGE_REQUIRED=1`
- **THEN** the gate fails; the build does not upload a stub report
  in place of real coverage.

#### Scenario: Tool missing locally passes

- **WHEN** a developer runs `make coverage-floor` locally and the
  tool is not installed AND `OPENPANEL_COVERAGE_REQUIRED` is not
  set
- **THEN** the gate prints a skipped status and exits zero.
